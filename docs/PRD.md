# PRD: MLQA — библиотека вопросов с ML-собеседований

| | |
|---|---|
| Статус | Черновик v0.1 |
| Дата | 2026-09-25 |
| Владелец | @aimnoux |
| Исполнитель по контенту | Claude (см. [CLAUDE.md](../CLAUDE.md)) |

## 1. Проблема

Вопросы с ML-собеседований разбросаны по телеграм-каналам, статьям и личным заметкам. У них нет общих свойств:
- непонятно, какие вопросы **реально** задают и насколько часто;
- подборки делят вопросы по ролям, хотя на разных ролях спрашивают одно и то же: Python, метрики, трансформеры;
- к вопросам дают готовые «ответы для собеса», которые разваливаются на первом же уточнении;
- одни и те же вопросы повторяются в разных формулировках.

## 2. Решение

Публичный статический сайт с базой вопросов из записей реальных собеседований:
- вопросы сгруппированы **по темам**, роль — только фильтр и статистика;
- у каждого вопроса есть **счётчик упоминаний** и список ролей, где его задавали;
- дубли объединяются: у вопроса одна каноническая формулировка и список реальных вариантов;
- уточняющие вопросы вложены в родительский;
- к каждому вопросу есть **теория**, достаточная, чтобы ответить самостоятельно.

База пополняется так: пользователь присылает материал собеседования, Claude обрабатывает его по регламенту из CLAUDE.md и коммитит изменения, сайт пересобирается автоматически.

## 3. Цели и не-цели

**Цели**
1. Каждый обработанный собес за один проход превращается в структурированные записи в базе без дублей.
2. По сайту можно готовиться: открыть тему и прочитать самые частые вопросы с теорией.
3. Статистика (сколько собесов, вопросов, упоминаний по темам и ролям) видна в README и на сайте и никогда не расходится с данными.
4. Бесплатно: GitHub + GitHub Pages, без серверов, БД и платных сервисов.

**Не-цели**
- Хранить или публиковать записи собеседований, транскрипты и любые сырые материалы.
- Давать «готовые ответы для собеса».
- Каталогизировать HR-вопросы и вопросы в духе «расскажи о себе».
- Решать live-coding-задачи в формате LeetCode. Из таких задач берём только знания, нужные для решения.
- Аккаунты пользователей, комментарии, серверная логика.

## 4. Пользователи

| Кто | Что нужно |
|---|---|
| Кандидат, который готовится к собесу | Понять, что спрашивают чаще всего, и разобраться в теории по теме |
| Кандидат с конкретной ролью (например, LLM) | Посмотреть вопросы, которые задавали именно на этой роли |
| Владелец репозитория | Быстро добавлять собесы, не думая о форматах и дублях |
| Claude | Однозначный регламент и формат данных, по которым можно проверить результат |

## 5. Функциональные требования

Приоритеты: **P0** — нужно для запуска, **P1** — вскоре после запуска, **P2** — когда-нибудь.

### 5.1 Модель данных — P0

- **Таксономия** (`content/taxonomy.yaml`): два уровня, раздел → тема. Роли в таксономии не участвуют.
- **Вопрос** (`content/questions/<section>/<topic>/<id>.md`): Markdown с YAML-frontmatter. Поля: `id`, `title`, `parent`, `aliases`, `tags`, `related`, `difficulty`, `status`, `created`, `updated`. Тело — теория. Формат — `templates/question.md`.
- **Собеседование** (`content/interviews/<YYYY>/<id>.yaml`): `date`, `company` (может быть пустым), `role`, `grade`, `stage`, `source`, `processed`, список `questions` с `q`, `asked` и `followups`. Формат — `templates/interview.yaml`.
- Все производные величины (упоминания, роли вопроса, статистика) **вычисляются** из этих файлов и нигде не хранятся вручную.

### 5.2 Упоминания — P0

- `mentions(q)` = число собеседований, где прозвучал `q` (в основном списке или в уточнениях); внутри одного собеса вопрос считается один раз.
- Для родительского вопроса дополнительно показывается сумма упоминаний его уточняющих вопросов.
- По каждому вопросу доступна разбивка упоминаний по ролям и грейдам.

### 5.3 Дедупликация — P0

- Критерий: два вопроса — дубли, если для ответа нужна одна и та же теория. Правила — в CLAUDE.md.
- Все реальные формулировки сохраняются в `aliases` и показываются на странице вопроса.
- P1: `scripts/find_similar.py` — поиск кандидатов в дубли по эмбеддингам (мультиязычная модель, локально). Решение всё равно принимает Claude.
- P1: периодическая проверка всей базы на дубли и слияние с сохранением URL через редирект.

### 5.4 Уточняющие вопросы — P0

- Уточняющий вопрос — отдельная сущность с полем `parent`: у него своя теория и свой счётчик.
- Вложенность — один уровень.
- В списках уточняющие вопросы отображаются внутри родителя (сворачиваются), на странице родителя — отдельным блоком со счётчиками.

### 5.5 Сайт — P0, если не указано иное

| Страница | Содержимое |
|---|---|
| Главная | Поиск, ключевые цифры, разделы с числом вопросов, топ частых вопросов |
| Раздел | Темы раздела; вопросы внутри темы отсортированы по упоминаниям |
| Вопрос | Формулировка; мета: упоминания, роли, грейды, сложность, статус теории; реальные формулировки; теория; уточняющие вопросы; связанные вопросы; хлебные крошки |
| Топ вопросов | Все вопросы по убыванию упоминаний |
| По ролям (P1) | Вопросы, которые задавали на конкретной роли, по убыванию частоты |
| Новое (P1) | Недавно добавленные вопросы и собесы |

Сквозные требования:
- полнотекстовый поиск по `title`, `aliases` и теории с поддержкой русского языка;
- формулы (KaTeX или MathJax), подсветка кода, тёмная тема, нормальная вёрстка на телефоне;
- стабильные URL вопросов вида `/q/<id>/`, которые не меняются при переносе вопроса в другую тему;
- вопросы без теории (`status: todo`) видны, но помечены как «теория в работе».

P2: отметка «изучено» в `localStorage`, режим тренировки (случайный вопрос из темы, теория скрыта до раскрытия), фильтры по грейду и сложности.

### 5.6 Статистика в README — P0

Блок между `<!-- STATS:START -->` и `<!-- STATS:END -->` генерирует `scripts/stats.py`:
- бейджи: число собесов, число вопросов, доля вопросов с готовой теорией;
- таблица с ключевыми цифрами;
- таблица по разделам: число вопросов и упоминаний;
- таблица по ролям: число собесов;
- топ-10 вопросов по упоминаниям со ссылками на сайт;
- дата обновления.

CI проверяет, что блок актуален (`stats.py --check`), и падает, если нет. Бот сам в репозиторий не коммитит.

### 5.7 Валидация — P0

`scripts/validate.py` проверяет:
- схемы frontmatter и YAML;
- уникальность `id` и совпадение с именем файла;
- наличие раздела и темы в таксономии;
- что все ссылки (`parent`, `related`, `q` в собесах) ведут на существующие вопросы;
- глубину вложенности не больше 1;
- отсутствие медиафайлов в коммите.

Скрипт запускается локально и в CI.

## 6. Входные данные и пайплайн обработки

### Что может прислать пользователь (от лучшего к худшему)

| Формат | Комментарий |
|---|---|
| Транскрипт (`.txt`, `.srt`, `.vtt`, `.docx`) | Лучший вариант: быстро и без потерь |
| Готовый список вопросов | Самый быстрый путь; формулировки близки к оригиналу |
| Аудио (`.mp3`, `.m4a`, `.ogg`) | Транскрибирует Claude. Желательно моно, 16 кГц, 32–64 кбит/с: это 15–30 МБ на час |
| Видео (`.mp4`) | Работает, но файл большой. Лучше заранее извлечь звук: `ffmpeg -i in.mp4 -vn -ac 1 -ar 16000 -b:a 48k out.mp3` |

К материалу нужны метаданные: **роль, грейд, дата, этап, компания** (или «не указывать»). Их можно написать одной строкой в сообщении.

Если собес записан в Granola (коннектор подключён), достаточно назвать встречу: Claude возьмёт транскрипт оттуда.

### Транскрибация

- `scripts/transcribe.py` (M3): faster-whisper (`large-v3-turbo`, `language=ru`), на входе аудио или видео, на выходе `.txt` с таймкодами в `inbox/`.
- Скрипт можно запустить у себя на машине, если облачный контейнер не справляется с объёмом или временем.
- Разделение по спикерам не обязательно: вопросы интервьюера Claude определяет по контексту.

### Шаги обработки

Подробно — в CLAUDE.md, раздел «Процесс»: материал → текст → выписанные вопросы → сопоставление с базой → запись собеса → обновление и создание вопросов → теория → валидация и статистика → коммит → отчёт пользователю.

## 7. Архитектура и стек

```
content/ (YAML + Markdown)
   │
   ├─► scripts/validate.py ──► ошибки в CI
   ├─► scripts/stats.py ─────► блок статистики в README.md
   └─► scripts/build_site.py ─► build/docs/ (сгенерированный Markdown: страницы тем, топы, мета вопросов)
                                   │
                                   └─► mkdocs build ─► build/site/ ─► GitHub Pages
```

| Компонент | Выбор | Почему |
|---|---|---|
| Язык скриптов | Python 3.11+ | Привычен DS-аудитории; одна экосистема для скриптов, транскрибации и эмбеддингов |
| Генератор сайта | MkDocs Material | Русский поиск из коробки, формулы, код, тёмная тема, мобильная вёрстка; сайт собирается из Markdown без фронтенд-разработки |
| Хостинг | GitHub Pages | Бесплатно, деплой через GitHub Actions |
| CI/CD | GitHub Actions | На каждый push в `main`: validate → stats --check → build_site → mkdocs build → deploy |
| Транскрибация | faster-whisper, локально | Бесплатно, хорошее качество на русском |
| Поиск дублей | sentence-embeddings, локально | Бесплатно, без внешних API |

Исходные файлы контента не совпадают со страницами сайта: `build_site.py` генерирует страницы с уже посчитанными счётчиками, вложенностью и сортировкой. Поэтому контент можно переорганизовать, не ломая сайт, и наоборот.

Если MkDocs перестанет развиваться, генератор можно заменить (Zensical, Astro): данные в `content/` от него не зависят.

## 8. Нефункциональные требования

- **Стоимость:** 0 ₽. Никаких платных API и серверов.
- **Приватность:** в репозитории нет записей, транскриптов и персональных данных. Компания указывается только с согласия владельца.
- **Воспроизводимость:** сайт и статистика полностью пересобираются из `content/` одной командой.
- **Масштаб:** до ~5 000 вопросов и ~1 000 собесов без деградации сборки (цель — меньше 2 минут в CI).
- **Качество теории:** без выдуманных фактов и источников; `status: done` ставится только после вычитки.

## 9. Метрики успеха

| Метрика | Цель |
|---|---|
| Обработано собесов | Растёт; видно в README |
| Доля вопросов с `status: done` | ≥ 80 % |
| Дубли, найденные постфактум | < 5 % от новых вопросов за месяц |
| Время от присланного материала до коммита | Один сеанс работы с Claude |
| CI зелёный на `main` | Всегда |

## 11. Риски

| Риск | Что делаем |
|---|---|
| Дубли накапливаются по мере роста базы | Жёсткие правила в CLAUDE.md, поиск по эмбеддингам (M3), периодическая проверка всей базы |
| Ошибки или выдумки в теории | Правило «только проверяемые факты», статусы `draft`/`done`, вычитка |
| NDA и претензии компаний | Нет записей и дословных задач целиком; компания — только по согласию |
| Для GitHub Pages на бесплатном плане нужен публичный репозиторий | Репозиторий публичный: в нём и так нет ничего приватного |
| Большие видео не пролезают в чат или транскрибируются слишком долго | Предпочтительный формат — аудио или транскрипт; `transcribe.py` можно запустить локально |
| Таксономия устаревает | Правила добавления тем; `id` тем стабильны, URL вопросов от темы не зависят |

3. **Нужен ли английский** в будущем. Сейчас — нет, всё на русском.
