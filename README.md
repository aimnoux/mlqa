## Что это

Здесь собираются вопросы из записей **реальных** собеседований. Каждое собеседование разбирается на вопросы, они сверяются с базой, раскладываются по темам и получают разбор.

- **Темы, а не роли.** Python спрашивают везде, трансформеры — и у LLM-щиков, и у AI-инженеров. Поэтому вопросы разложены по смыслу: *раздел → тема → вопрос*. Роль — это фильтр, а не папка.
- **Теория, а не шпаргалка.** Разбор объясняет, как всё устроено, чтобы человек ответил своими словами и выдержал уточнения. Готовых ответов «для собеса» здесь нет.
- **Счётчик упоминаний.** Видно, как часто вопрос встречается на реальных собесах и на каких ролях.
- **Без дублей.** «Расскажи про attention» и «Как работает self-attention?» — один вопрос с несколькими формулировками.
- **Уточняющие вопросы вложены.** «А зачем делить на √dₖ?» лежит внутри вопроса про self-attention.

## Как устроен репозиторий

```
mlqa/
├── content/
│   ├── taxonomy.yaml          # разделы и темы — единственный источник правды
│   ├── questions/             # вопросы: <раздел>/<тема>/<id>.md — frontmatter + теория
│   └── interviews/            # записи о собесах: <год>/<id>.yaml — какие вопросы прозвучали
├── templates/                 # шаблоны вопроса и собеседования
├── docs/
│   └── PRD.md                 # требования к проекту и роадмап
├── scripts/                   # (M1) валидация, статистика, сборка сайта, транскрибация
├── overrides/                 # (M2) оформление сайта (MkDocs Material)
├── mkdocs.yml                 # (M2) конфиг сайта
├── CLAUDE.md                  # инструкции для Claude: как вести базу
└── README.md
```

Счётчик упоминаний нигде не хранится вручную: он **считается** по файлам `content/interviews/`. Статистика выше и сайт собираются из тех же данных.

Видео, аудио и транскрипты собеседований **в репозиторий не попадают**: они лежат локально в `inbox/`, который есть в `.gitignore`.

## Как пополняется база

1. Появляется материал собеседования: видео, аудио, транскрипт или просто список вопросов.
2. Материал переводится в текст, из него выписываются вопросы и уточнения.
3. Каждый вопрос сверяется с базой: это уже существующий вопрос (тогда +1 упоминание и, возможно, новая формулировка), новый вопрос или уточнение к существующему.
4. Создаётся запись о собеседовании в `content/interviews/`, для новых вопросов пишется теория.
5. Статистика и сайт пересобираются автоматически.

Подробный процесс описан в [CLAUDE.md](CLAUDE.md), требования и планы — в [docs/PRD.md](docs/PRD.md).
